# mtDetail（明细模块）恢复计划与验收标准

版本：2026-09-13；状态：**规划，未开始独立生成器实现**。配合 [接手入口](START_HERE.md) 与 [开发沿革](DEVELOPMENT_HISTORY.md) 使用。

本文的候选功能是核对和实施任务，不代表已证明原版支持，也不自动扩大用户授权。凡原版不支持/用户不要求的功能，确认后标“不适用”，不强行补做。

## 1. 现有证据和缺口

| 证据 | 已确认事实 | 不能据此推断 |
|---|---|---|
| Document、Moduletype | 六种类型包含mtDetail，选择界面已有入口 | 不代表可生成可运行模块 |
| GenerateRunFrame | 当前无mtDetail独立分支 | 不能让它落入编辑模板后宣称完成 |
| 精灵页面控制 | mtDetail显示数据结构、从表结构；当前查询条件页只对Multiple/Report显示，透视页只对Report显示 | 不随意给mtDetail加透视/条件页；查询按钮可能走弹出查询窗体，需原版核对 |
| NormalSetting | mtDetail有“关联字段”“记录编号”“从表唯一”“从表非空”“隐藏字段-从表”等适用项 | 记录编号不能直接等同主单号或主从模板的明细行号 |
| FunctionButton | 有查询、首上下一末导航、编辑、导入、输出等目录适用信息 | 每一按钮真正影响主表还是明细、保存粒度仍未知 |
| 七组fixtures/reference | MasterSlave、MasterSlaveQuery、Multiple、MultipleEditor、Report、Tree、TreeEditor | 没有mtDetail黄金JSON/DFM，不应改文件名冒充 |
| 本次文件名盘点 | 找到TWEBDETAILEDSTRUCTURE资源，没有发现以mtDetail命名的样例文件 | 不证明所有附件/数据库中都不存在；接手可继续按配置内部类型搜索 |

相关源码入口：

- `src/ugWebConfigurationModule.pas` 页面适用逻辑。
- `src/ugWebConfigurationModule.GenerateRunFrame.pas` 生成路由。
- `src/ugWebConfiguration.NormalSetting.pas`：3000“记录编号”是SetupAutoNumber，针对mtDetail；3002“明细编号”目前针对mtMasterSlave。
- `src/ugWebConfiguration.FunctionButton.pas` 功能适用目录。
- `src/ugConfiguration.Document.pas` 配置类型合法性。

## 2. 开始实现前的证据任务（G0）

先检索工作区已有资源、附件和配置导出，找到则复用，不重复索取。若缺少，请用户从原DLL生成一个最小mtDetail模块，提供同一版本的：

1. 配置JSON（确认TWebModuletype确为mtDetail）；
2. 完整生成DFM，含Codes.Strings和Events.Strings；若另给脚本，核对与DFM一致；
3. 初始界面、查询/新增/修改操作截图；
4. 测试库类型、主表/从表字段类型、主键和关联关系；无需生产凭据；
5. 若使用查询或编辑子模块，提供该子模块配置/变量调用约定。

最小数据建议：主记录A含两条明细，主记录B含一条明细，主记录C无明细；再准备可安全测试的同名不同键值。编号、关系、行数可客观对比。所有写入使用测试库/副本，经用户确认后执行。

### G0必须回答的业务问题

- 这是按主记录导航的明细维护页，还是独立明细列表？主表是否可编辑？
- 导航切换的是主记录还是明细行？无明细主记录如何显示？初始化打开哪条？
- “关联字段”来自哪个配置区块，如何映射父/子字段？JSON别名是否分区独立？
- “记录编号”目标字段、编号方式、生成时机和唯一性范围是什么？不得凭GUID样例限制全部方式，也不凭其他模板引入DBAutoincrement。
- 新增、删除、导入、保存是否只影响当前主记录的明细？批量选择范围是当前页还是全部加载？
- 从表唯一是当前主记录内、整张表还是组合字段范围？先证明再写SQL。
- 是否行内编辑、弹出mtEditor或其他子窗体？输入/输出变量和取消行为是什么？
- 是否分页？若分页，暂存、跨页、导航、保存/定位如何交互？
- 权限从哪一表/字段取，是否依赖层级权限、查询窗体和当前账号信息？
- 支持哪些下拉/关联/导入/输出？打印仍通过哪个原入口？

**G0完成条件：**建立JSON→控件→脚本→数据操作映射表；每项标“原版证实/当前代码线索/待确认/不适用”。关键写入语义没确认前只做读取与计划，不猜写回范围。

## 3. 实现结构建议（不是既有文件）

建议新增小范围模块，命名可随实现调整：

| 建议单元 | 职责 |
|---|---|
| ugConfiguration.DetailPlan.pas | 解析适用配置、表键/关系/字段映射、能力校验与错误原因 |
| ugConfiguration.DetailTemplate.pas | 生成控件DFM、脚本与事件；协调子功能 |
| ugConfiguration.DetailWrite.pas | 明细暂存、编号、校验、保存/撤销状态（若G0证实需要） |
| 共用已有单元 | 复用合适的查询/下拉/校验/提示组件，而非复制整个主从模块 |

在GenerateRunFrame增加明确mtDetail路由，接入现有备份、设计解绑、DFM加载、验证、失败恢复。若引入参考资源，保证黄金样例不会绕过动态生成能力检查。

不支持的配置在**清理旧界面前**给出准确诊断，保留原模块；不要“生成成功”但忽略按钮或关键设置。新增校验不能误拒绝原版合法组合。

复用需注意：MultipleRecord是共享单元、Report经MultipleTemplate入口、DetailLookupBridge是主从明细下拉桥。复用前明确依赖的数据集名、事件、主键、事务范围；不得全局搜索替换名称后直接交付。

## 4. 分阶段工作与交付闸门

### G1：只读界面和查询/导航

工作：动态DFM、主/从绑定、关系参数、初始加载、空数据、字段标题/组别/隐藏、工具栏图标尺寸、非可视布局。按G0决定导航/查询窗体/分页，不额外创建未证明的透视功能。

退出标准：基础JSON可完成生成与再次打开；主A/B/C显示正确；查不到数据不保留前一单明细；权限空集不变成全表查询；控件/脚本在真实宿主可加载，无乱码/空白窗/重复销毁。

交付：最小JSON/DFM/脚本、能力矩阵、只读验收条目。若暂不支持写按钮，应说明这是中间批次，不宣称整个mtDetail恢复完成。

### G2：明细新增/修改、编号、校验、保存/撤销

工作：稳定键定位，字段名读写；新增继承经确认的父键，保存范围只包括授权明细；记录编号按原版方式接入；标题必填/唯一/引用校验，失败保留输入。审计配置和业务字段冲突先明确规则，不能照搬树规则。

状态至少区分：未就绪、浏览、编辑/暂存、提交中、已提交待重载。提交失败保留暂存，提交成功刷新失败不重复提交，已提交状态不能回滚成未提交提示。

退出标准：A和B不串数据，编辑确认/取消正确，先前暂存不丢；无Delta/字段恢复原值不报错；新增/修改/删除按主键作用到正确记录；保存/撤销后显示与数据库一致。

### G3：原版支持的下拉/关联、批量操作与权限

工作：引用字段、SQL下拉、返回代码/显示名称、联动字段；输入防抖、关闭/切行取消过期回调；关联展示字段只读；多选删除/导入（若支持）按真实选择集；查询、导航、导入、保存的权限一致。

退出标准：Upper/Lower不破坏代码；多匹配阻止保存；无权限记录不因独立条件/空条件/直接键值访问露出；多选操作不退化成当前一行；重复编号/引用失败显示清楚并保留可重试状态。

### G4：表现、原打印附件与整体稳定性

工作：适用的列宽/顺序/显隐/组头、复制/排序/过滤；统一SweetAlert、LT、必填焦点；保留原打印入口和模板绑定方式；精灵反复完成、切换模板、失败恢复和关闭资源释放。

退出标准：所有声明支持项完成本地与用户宿主验收；不适用/暂缓/未测项逐条记录；共享模块无已知新增回归。未经确认不以“其他模板已通过”代替本模板新路径验证。

## 5. 验收清单（全部初始待执行）

执行记录必须含：版本哈希、JSON、测试库类型、实际行为/证据、结果。结果只能是“通过/失败/未测/不适用（理由）”。本表不是已经通过的清单。

| ID | 场景 | 客观通过标准 |
|---|---|---|
| D01 | 新配置、完成、重开再完成 | 配置不丢；控件事件完整；无重复对象/undefined/空白窗 |
| D02 | 配置不支持或加载失败 | 明确原因；旧配置/界面可恢复，不留下半生成状态 |
| D03 | 名称、组头、隐藏与非可视布局 | 标题正确中文、必填clRed、隐藏字段不显示；数据键仍保留；图标/尺寸对齐原版 |
| D04 | A/B/C导航与首次加载 | 只显示当前范围；无明细时清空，不能显示上条残留；导航边界状态正确 |
| D05 | 查询、空值、单引号及数字日期 | 参数类型正确，空条件行为符合原版，无字符串拼接注入或旧参数残留 |
| D06 | 新增两条不同值明细 | 名称/代码/数量/备注逐字段正确；父键相同但行键不混淆 |
| D07 | 修改非第一条、改列布局后再修改 | 按键更新目标行；其他记录不变，不按当前列序号回填 |
| D08 | 确认/取消及连续新增修改 | 取消不提交；确认保留暂存；连续操作可用，无closed dataset |
| D09 | 必填/唯一/引用失败 | 不提交、显示业务标题和失败行，关闭提示后定位；修正可继续，早先暂存保留 |
| D10 | 删除/多选删除（若支持） | 删除真实选择集；取消无变化；不影响其他父记录和关联展示表 |
| D11 | 记录编号 | 按已确认方式/时机生成；重复与取消处理正确；不替代主单号/行次；并发未测需注明 |
| D12 | 保存成功及重新查询 | 数据完整，定位按原版/已确认规则，其他主记录不被覆盖 |
| D13 | 保存失败、成功后刷新失败 | 前者可重试且暂存保留；后者提示已保存成功并禁重复保存，重载恢复 |
| D14 | 撤销/字段改回原值/无变化保存 | 无Delta时无异常；撤销恢复正确范围和选择；不丢已提交数据 |
| D15 | 有暂存时切主记录/翻页/关闭 | 按G0约定提示或阻止；不能悄悄丢失/带入其他单据 |
| D16 | 分页（若支持） | 查询/页大小重置一致，空末页正确；跨页保存定位/选择集语义明确 |
| D17 | 关联/下拉 | 展示与返回值正确，JOIN不重复写；多匹配报错；隐藏键不丢；选择代码大小写保持 |
| D18 | 连续输入退格/快速失焦 | 停止后检索；过期结果不覆盖新值；列表不跑左上角或异常关闭 |
| D19 | 导入（若支持） | 文本/Excel按字段映射，错误可查看，无阻塞ShowMessage；按确认范围保存 |
| D20 | 权限 | 查询/导航/写入同一范围，空权限不可全表，按钮许可不被刷新覆盖；不自行豁免admin |
| D21 | 列布局/分组/排序过滤（适用项） | 配置组头正确；显示顺序与存储字段映射独立；保存/重开一致；排序范围注明 |
| D22 | 输出/打印附件（适用项） | 使用原入口、正确数据绑定，权限/参数正确；不擅自拆出新打印模式 |
| D23 | SweetAlert与多语言 | 提示/确认/取消/输入空值分别正确，异常中止，焦点恢复，无业务继续提交 |
| D24 | 反复打开关闭/模板切换/退出 | 至少三轮；标题边框内容正常，无新增业务控制台错误/可归因泄露报告 |
| D25 | 已验收模板回归 | 共享变更影响范围内的主从/列表/报表/编辑/树测试通过；无源码未经说明的全局行为改变 |

## 6. 开发注意事项

1. 每个参数/组件调用必须核对FastScript实际注册。Delphi编译成功和模板字符串包含正确文本，不等于宿主脚本可执行。
2. 主表/从表键、关联别名、JSON字段序号、显示顺序分别建模；字段名对应变量，不能按列位置传值。
3. 临时数据集不要进配置保存遍历；JSON新对象立即建立所有权，失败释放；Edit/Post/Cancel成对，Bookmark释放成对。
4. 引用关联数据用于显示不能默认可写；禁止为了完成保存而更新所有JOIN表或无条件删除其他主记录数据。
5. 通用唯一校验与权限检查不可因Delta空就跳过。可参考现有快照/行状态修复，但需验证明细新增/修改/删除状态。
6. 不重新开放Catalog/Schema，不假设SQLite支持序列，不在MSSQL节点使用其他方言语法；数据库类型须由实际节点确认。
7. 不复制“强制设置窗口高度、重置全局layout计数、吞JS错误”等旧尝试。使用已验收设计解绑与对象释放路径。
8. DFM可见属性、脚本变量和生成后校验保持一致；隐藏字段不生成控件时，不要求FindComponent必须成功，也不丢必须的内部键。
9. 样例文件和共享测试可能陈旧；新增mtDetail固定最小样例和实际动作测试，编译完整脚本，而不只搜关键字符串。
10. 保留原版业务入口、用户要求中文按钮与事件命名格式；美化和架构清理不能顺带改变已验收功能。

## 7. 完工定义与交付清单

mtDetail只有满足以下条件才标记“本期验收通过”：

- G0业务模型和适用范围经确认；
- G1–G4声明支持项有实现及对应测试，D01–D25逐项给出结论；
- Debug/Release构建、DFM/脚本验证和用户真实宿主操作均有记录，未测不冒充通过；
- 所有失败项修复或经用户明确暂缓，不静默降级；
- 独立部署包含DLL哈希、配置JSON、生成DFM/脚本、测试记录、限制和备份替换/重新生成步骤；
- 更新START_HERE与验收记录，明确哪些公共未测项继续保留。

建议新增交付文档（实现时创建，不是现成文件）：`validation/MTDETAIL_EVIDENCE.md`、`MTDETAIL_ACCEPTANCE.md`；专项探针/测试按实际实现命名；deployment包按主题日期归档。
