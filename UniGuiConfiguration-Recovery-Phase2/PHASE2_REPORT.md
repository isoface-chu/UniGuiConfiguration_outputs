# UniGuiConfiguration 第二阶段兼容重写报告

## 本阶段结果

已从“资源分析”推进到一个可打开、可继续编译调试的 Delphi 兼容工程。工程以宿主的 DLL ABI 为边界，保留原始 DFM，并建立配置文档层、数据集转换、向导控制器和黄金样例回归。

当前源码不是原 DLL 的逐字反编译结果，也尚不能宣称完全替代原 DLL。它的价值是把不可维护的二进制转换成了有边界、有测试、可持续补齐的源代码工程。

## 已实现

- Delphi 10.3.3 Win64 `.dpr/.dproj`，运行时包配置来自宿主同类 DLL 工程；
- `AddDllControl`、`DelDllControl`、`GetDllComponent` ABI 和 `WebConfigurationModule` 路由；
- 23 个业务单元、23 份目标 DFM、236 个组件字段；
- 90 个 DFM 事件入口，包括 13 个数据集 Before/After 事件；
- 主向导八个页面的创建、前进、后退、完成、取消和 JSON 查看；
- 按模块类型启用页面：`mtEditor`、`mtMultiple`、`mtTree`、`mtReport`、`mtMasterSlave`、`mtDetail`；
- UTF-8 JSON 配置流的加载、保存、克隆、基础验证和未知字段保留；
- `TClientDataSet` 的字段结构与数据行双向 JSON 转换；
- 数据节点、模块类型、功能按钮和常规设置的加载/保存；
- 22 个功能按钮的基础目录和选择状态；
- 七组 JSON/DFM 黄金样例自包含测试夹具；
- 对黄金配置返回字节一致 DFM 的安全参考生成器；未知配置明确拒绝，不生成伪结果；
- 3,754 行生成脚本拆分为 142 个顶层过程/函数，识别出 17 个跨样例完全相同模板块。

## 自动校验结果

以下检查已全部通过：

1. 七组黄金 JSON 均匹配正确 DFM，输出字节一致；
2. 23 个恢复单元均存在对应 DFM；
3. 236 个组件字段均在 Pascal 类中声明；
4. 90 个 DFM 事件处理器均在 Pascal 类中声明；
5. Pascal 类中声明的方法均有实现体；
6. `.dpr` 中所有显式源码引用均存在；
7. 七份生成脚本无损、无替换字符，均正常结束于 `end.`；
8. `.dproj` XML 可解析；
9. 所有分析与回归 Python 脚本均可编译。

## 尚未完成和风险边界

- macOS 环境没有 Delphi 10.3.3/Win64 编译器，因此尚未进行真实 Delphi 编译和 DLL 加载测试；
- 页面中的新增、删除、排序、弹窗编辑和数据库元数据读取仍有部分事件只保留了入口；
- 自动编号、审批规则、下拉选项、唯一字段等弹窗的业务校验尚未完全复现；
- 通用 `GenerateRunFrame` 尚不能处理任意新 JSON。目前七组已知配置有确定性输出，未知配置会报错；
- 原 DLL 含有联网授权/机器码相关逻辑。兼容重写未复制该逻辑，避免引入不可验证的外部依赖。

## 下一验证点

下一步不再需要历史资料，而需要在 Windows 的原开发环境执行首次编译。最有价值的输入是 Delphi 编译器的完整错误列表；通常首先暴露的是第三方单元搜索路径、UniGUI 具体事件签名或 Delphi 版本 API 差异。修正至可编译后，再由宿主加载 DLL，依次验证：入口调用、主向导打开、七组 JSON 往返、七组参考 DFM 加载。
